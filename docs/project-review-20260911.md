# 项目审查与下一版建议

审查基线：`0.15.0-preview.5`，2026-09-11。目标是让 WebCodex 成为 Codex 额度不足时可用的本地工作替代入口，保留纯 MCP、统一配置、多设备/多工作区和跨平台要求。

本轮检查核心代码、工具说明、安装文档、测试及状态管理，并在隔离临时目录复现导入重试、二进制移动/删除和单文件提交中断行为。没有修改服务代码、真实配置或正在运行的隧道。上一轮完整回归为 768 项：766 通过、0 失败、2 项 Windows 文件符号链接权限跳过；本轮没有无变化重跑全套。真实 ChatGPT 的 PDF 正文与生成 PPTX 文件参数交接仍需独立验收。

## 实施更新

preview.6 已开始落实第 1、2、4、5 项及安装/组件构建问题，具体以[实现状态](implementation-status.md)和[测试记录](testing.md)为准。下文保留原审查基线和复现证据，不将修复后的行为追溯为旧版已具备。真实宿主验收、备份维护和工具分组仍待完成。

## 优先处理的实际问题

### 1. 工具说明与接入文档不一致（P1）

- `src/server-instructions.ts:9`、`src/document-tools.ts:57` 指引 PDF 使用 `document_open/document_read`；`src/server.ts:68`、`src/file-widget-probe.ts:39` 仍指引正常 PDF 分析走原生附件或手工上传。
- `docs/chatgpt-setup.md:3`、`:83` 仍要求版本 `0.14.0-preview.2`，`:87` 仍写 44 个工具、2 个私有工具。当前实际为 `0.15.0-preview.5`、56 个工具、8 个私有工具。

这会让模型选择错误流程，也会让用户把正确的新版本当作升级失败。优先统一文件类型对应工具的规则，并由一个能力清单生成工具描述、状态和当前验收提示。历史测试记录应保留历史版本，不做全仓库字符串替换。

验收：当前接入文档、工具导出和服务指引一致；PDF 文本读取不会再被服务自身的旧说明引导回手工上传。

### 2. 文件导入重试缺少稳定操作身份（P1）

`src/file-import.ts:41` 将含短期下载地址的文件对象纳入幂等摘要。隔离复现：首次保存成功，保持文件 ID、目标路径、操作键不变，只刷新下载地址，返回 `IDEMPOTENCY_CONFLICT`。未重复下载、未损坏文件，但不能用这一请求取回原成功回执。真实 ChatGPT 是否会自动刷新地址尚未验证。

此外，`src/store.ts:50` 永久重放已缓存的失败。实测第二次导入因 `FILE_IMPORT_BUSY` 失败后，即使前一项已结束，同键仍报忙；下载在写入前超时后，同键也不会再次下载。

建议增加只读 `operation_status`，按原操作键查询阶段、回执及关联变更；将短期传输凭据与稳定操作身份分离。明确未写入的暂时失败允许有界重试，提交状态不明则继续禁止盲目重放。不能简单删除 URL 校验、仅凭相同文件 ID 接受任意不同内容；需要记录并核对实际文件摘要。

验收：已完成操作可查询而不重复写入；凭据刷新有明确恢复路径；忙/下载超时不会变成永久死路；不确定提交不会自动重写。

### 3. 核心功能需要真实 ChatGPT 闭环验收（P1）

本地合法 PPTX 测试实际经过 MCP、下载器与文件系统，但远端文件响应是模拟的。官方文件参数 schema、HTTP 连通性、组件出现和 RPC 返回均不能代替宿主交接。

下一版发布前，至少在真实对话完成：中文文本创建/修改/冲突恢复、PDF 第 1 页及后续页未知内容校验、生成 PPTX 回存及磁盘哈希核对、指定 Codex 会话接续。记录版本、工具清单摘要、设备、成功阶段和实际结果，公开记录不含文件凭据。

### 4. 二进制文件“能存，后续管理不完整”（P2）

`src/file-batches.ts:105`、`:114` 的移动/删除仍使用文本写入预算。默认配置下，隔离测试的 **1,048,577 字节**文件可通过 `fs_import_file` 保存并用 `fs_stat` 查询，但批量移动和删除均报 `FILE_TOO_LARGE`。

建议补齐原字节文件的移动、复制、可恢复删除，统一其大小与批次预算；复用已有批处理入口或清晰的专用接口，保留设备/工作区检查、目标冲突检查和恢复记录。无需同步扩大文本编辑限额。

验收：10–32 MiB PPTX/ZIP 可保存、重命名、移动和恢复；文本限额、只读目录和跨工作区边界继续生效。

### 5. 单文件提交中断后的状态关联不足（P2）

`src/filesystem.ts:393` 创建变更记录，`:439` 在提交后标记成功；`src/store.ts:39` 启动时把未完成操作标为 `unknown`。隔离子进程在文件替换后退出：磁盘已有新文件，操作为 `unknown`，变更仍为 `pending`，同键返回 `EXECUTION_UNKNOWN`，旧字节备份保留。

这是已保留安全边界但缺少易用恢复入口的情形，不是已证实的数据丢失。建议把操作键、变更 ID、下载/提交/校验阶段关联起来，提供启动后只读核对和明确恢复建议。当前文件匹配新摘要只能作为观察，不能自动证明原操作已完整成功。

验收：在备份后、替换后、回执前分别中断，都能查询到一致的记录和当前磁盘观察；不重复执行、不自动覆盖。

### 6. 长期运行缺少存储保留策略（P2）

`src/filesystem.ts:393` 保存完整旧文件字节，`src/store.ts:37`、`:66` 的操作与审计记录持续增长；作业输出也持续保存。当前只有协议诊断等局部数据有界，不能据此认为整个状态目录有界。

建议在统一配置加入备份/日志总量与保留期，提供占用统计、清理预览和本机显式清理。保护未完成、未知状态和指定保留的恢复记录。应另行处理 SQLite 空间回收，不能只删除行后宣称磁盘空间已经释放。

### 7. 常用工具与实验诊断工具需要分组（P2）

当前 48 个公开工具中包含旧原文件组件和合成阅读探针；`src/server.ts:97` 无条件注册这些入口。不能据此断言它们造成 ChatGPT 漏工具，但普通任务确实会收到与主流程无关的选项和长说明。

建议统一配置提供常用模式与诊断模式，常用模式隐藏旧探针，保留必要的组件私有调用和有限旧资源兼容。`system_status` 分别报告服务实现、工具清单和有依据的业务观察；不要将固定的 `host_verified:false` 当成每次请求失败，也不要将 `response_sent` 当成任务完成。

### 8. 安装与发布仍可简化（P2）

当前以克隆源码、安装 Node/Git/rg、构建及安装官方客户端为主；Windows 有安装脚本，Linux/macOS 仍需手工配置。三平台 CI 已配置，但本地未提交改动不能用旧提交的 CI 结果证明兼容。

还有明确的配置适配缺口：`scripts/install-tunnel.ps1:13` 安装到仓库 `.webcodex/tools`，而 `src/config.ts:48` 默认按 `${configDir}/tools` 查找。配置移到另一目录时，安装脚本与 `clientPath=auto` 的默认查找位置不一致，需要手工调整。建议提供 `tunnel install --config …`，统一使用所选配置的 `toolsDir`，同时处理平台/架构。

建议提供固定版本的 GitHub Release 构建产物、校验摘要和三平台安装指引，并增加在隔离测试目录运行的本机自检。自检覆盖中文路径、多工作区、读写、二进制保存和配置发现，输出脱敏诊断报告。安装/升级应识别运行版本与磁盘版本，正常退出并保留配置；不要未经确认强制终止现有作业。既有二进制 fixture 的公开审核项仍需在发布前处理。

### 9. 同版本构建时的组件发布需要原子化（P2）

`scripts/build-document-widget.mjs:95` 直接覆盖最终 JS，`src/document-widget.ts:12` 按请求读取该文件，只校验最终 HTML 大小。无真实文件修改的故障注入中，读端会接受残缺 JS 并返回 HTML；实际并发构建的时间窗口尚未复现。现有按版本保存的方案解决了跨版本混用，没有覆盖同版本覆盖中的半写入。

建议构建到临时文件，完成长度和 SHA-256 检查后原子替换；组件读取与 doctor 通过构建清单检查资源完整性。验收同版本构建期间请求仍得到完整旧版或完整新版，损坏资源给出明确本地错误。

## 推荐实施顺序

1. **下一小版本：稳定性收尾。** 统一指引与文档；完成真实 ChatGPT 验收；补上操作查询和导入重试；修复二进制管理限额。暂不扩大第三方服务或浏览器扩展依赖。
2. **随后版本：日常维护。** 单文件中断恢复、备份配额与清理、常用/诊断工具分组、安装自检和升级提示。
3. **稳定后再扩展。** PDF 独立大文件预算与长文档读取、更多格式支持、Git 写操作、可选交互终端。PDF 当前仍复用最多 7 MiB 的原文件传输配置；解除该耦合必须同时设计总内存、时间及分页预算，不能只调大一个常量。

这些是实施建议，不代表本轮已经修复或已通过真实宿主验收。
