# 当前功能状态

版本：**0.16.0-preview.7**。源码仓库：[xq3427/WebCodex](https://github.com/xq3427/WebCodex)。当前为预览版，未发布 npm 包。

| 方向 | 当前状态与边界 |
| --- | --- |
| 配置与跨设备 | JSON/TOML 单文件配置、独立设备/工作区身份、可配置目录与程序路径；没有跨设备同步或调度 |
| 多工作区 | 字符串/对象简写、名称/权限、启停、离线策略和显式 worktree 登记 |
| 文本与代码 | 读取/搜索/长行续读/批量读取、创建/写入/补丁、读回哈希 |
| 本机文件复制 | fs_copy 在同一设备的已授权工作区间直接复制原字节，源可只读；无需上传/URL/命令执行，含哈希校验、备份和持久操作状态 |
| 生成文件回存 | 默认 `fs_save_file` / `fs_save_file_status`：真实宿主文件 ID 由组件私下解析，或使用官方文件对象直接下载；写前核对原件大小/哈希，无需用户填 URL 或模型 Base64；真实 ChatGPT 端到端验收待完成 |
| 修改恢复 | 记录服务文件操作、原字节备份、文本或二进制元数据预览和有条件恢复；不能恢复任意程序副作用 |
| 批量修改 | 预检/计划哈希/应用/状态与失败恢复；不承诺跨文件原子事务 |
| Git | 只读状态和差异；没有专用 stage/commit/push |
| 程序执行 | 页面总开关，开启后支持本机程序名/绝对路径及显式 CMD 命令；修复带路径引号的单条命令，旧 allowlist 与程序预设兼容，保留等待/日志/取消/pipe stdin；没有 OS 沙箱和 PTY |
| Codex 历史 | 可选只读可见记录、分页/搜索/交接；不调用模型、不恢复隐藏上下文 |
| 任务与检查点 | 独立任务及不可变修订、当前文件/作业观察、交接导出；不是自动执行器 |
| MCP 与官方隧道 | stdio/回环 HTTP、统一配置的官方客户端启动、锁/健康/协议诊断 |
| 本地控制中心 | `connect` 默认同时启动并输出临时凭据链接；五页配置表单、密钥只写更新、字段级错误定位、配置版本检查和原子保存、自有隧道或 HTTP 服务启停重启；保留文件/会话查看 |
| 本机文件交给 GPT | 原字节及显式组件诊断保留；自动加入原生附件未实现、仍暂停；PDF 文字层由独立原型提供 |
| 组件正文回传 | 合成文本已在真实 ChatGPT 连续成功两次；PDF.js 浏览器解析及 0.15.0-preview.4 内置字体/CMap 修复仍待 PDF 宿主验收 |
| 浏览器/Actions/公网 | 不在默认依赖、命令或工具中；历史实验配置不激活功能 |
| 开源资料 | 中英文 README、配置示例、MIT、贡献/安全说明、依赖许可、CI 和仓库检查 |

当前 65 个注册工具包含 55 个常规工具和 10 个组件私有工具，详见 [schema](tools.json)。ChatGPT 是否向当前对话提供某工具、是否实际调用成功，需要宿主侧确认。

## 本版已实现与已验证范围

0.16.0-preview.7 支持宿主文件对象直接下载，以及组件 `getFileDownloadUrl` 私有交接。票据绑定设备、工作区、目标、原件及覆盖条件。写入前独立核对源大小/哈希；组件成功回执也必须匹配原件摘要、工作区、操作键、路径、大小和设备。旧组件元数据与当前目标不符时停止，不提交旧票据。状态查询非阻塞，最多观察 30 次 pending；重启后可查询持久结果，未完成票据不会自动恢复或重做。

模拟宿主测试覆盖完整 2,341,397 字节合法 PNG 及保存链路；本地 stdio 测试已验证跨工作区复制、源只读和执行关闭时的完整原字节保存。它们均未操作用户原图，也不能证明真实 ChatGPT 已授权当前生成文件。构建、专项、全量首次失败及补跑记录分别见[测试说明](testing.md)，不把受限权限跳过或补跑结果记为全量通过。

2026-09-11 真实回存反馈：64 KiB 原字节块在 Code Interpreter 转交给模型时被截断，未提交 `fs_write_binary_chunk`；同期本地隧道正常、只读调用已响应。该次失败发生在宿主字节交接，不在本机块接收或文件权限。模型指引改为有条件的小载荷验收，发生截断就停止，不推荐数百次 Base64 中转。详情与官方文件对象直传的待验收边界见[回存说明](file-writeback.md#真实网页失败与当前边界)。

0.16.0-preview.5 调整原字节回存限额：分块默认 64 KiB，可配置 1–256 KiB；整文件取 `limits.binaryWriteMaxBytes`（默认 32 MiB，最大 128 MiB）与 `binaryInputs.maxCacheBytes`（默认 64 MiB，范围 1 KiB–512 MiB）的较小值。单消息 `fs_write_binary` 的内联限额仍默认 256 KiB，不再限制分块整文件。显式较小旧配置继续生效；不得为适应限额缩图或重新编码。服务接收预算不保证 ChatGPT 能完整传送大段 Base64，本段不代表本版测试或真实宿主验收已通过。

0.16 的管理接口仅在本机面板提供，不加入 MCP 工具列表。默认 connect 同时启动服务与控制中心，并在终端输出完整临时凭据链接；页面直接管理同次启动的服务。查看状态不取得独占状态租约；重启使用确认的配置版本，并拒绝活动作业或外部启动器接管。旧版或无面板启动的外部服务需先正常停止一次，再由面板启动。只打开面板不代表 ChatGPT 已连接；面板端口变更在下次启动面板生效。使用说明见[控制中心](local-panel.md)。

## 宿主验收与功能边界

自动保存和兼容导入共用本机下载器，只允许 `https://files.oaiusercontent.com`，复用可选 `tunnel.proxyUrl`；它们不需要用户的公网服务器、证书、扩展或额外 API key。`FILE_IMPORT_SOURCE_DENIED` 表示本机下载来源校验拒绝，不能解释为所有本机文件工具都无权限。本机目录之间复制应使用 `fs_copy`，不走下载接口。

此前 PDF 网页验收均未取得正文。0.15.0-preview.3 已通过原文件校验，但组件在提取期间报告资源失败；日志记录资源请求在失败提交后约 82 秒才到本地服务，随后 72 毫秒成功返回。0.15.0-preview.4 将资源清单中的字体与 CMap 内置到组件，消除解析期间的资源工具调用，并保留安全的底层错误原因；具体宿主排队原因仍未知。执行结果见[测试说明](testing.md)。

旧 `fs_import_file` 和 Base64 单消息/分块工具继续保留为兼容入口。此前宿主传入 `sandbox:/...` 时未能导入，后来模型中转原字节也发生截断；这些历史失败不能算作当前自动保存入口已经验收。默认二进制单文件上限为 32 MiB，可配置至 128 MiB；自动保存不受分块缓存预算限制，仍须满足宿主授权和下载条件。详情见[生成文件回存](file-writeback.md)。

备份总量维护、诊断工具分组和跨平台实际 CI 结果列于[路线](roadmap.md)。当前验收入口由工具导出生成，见[版本验收](current-acceptance.md)。更新代码后需要构建、正常重启已有连接并更新宿主工具定义；旧服务不会自动加载新代码。
