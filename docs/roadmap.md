# 后续路线

本次优先完成可审阅的公开源码和文档，功能状态以[实施状态](implementation-status.md)为准。

## 优先：发布与稳定性

1. 创建 GitHub 仓库后运行 Windows/Linux/macOS CI，修复实际平台差异，再决定正式版本范围。
2. 在真实 ChatGPT 对话完成设备识别、文本读写/冲突恢复、Codex 接续和可选执行的独立验收。
3. 改进工具发现失败和连接锁的诊断；避免模型误把“有工具列表”或“隧道在线”当成操作成功。
4. 制定状态库、备份、作业日志的保留与安全清理策略，支持预览和范围确认。

## 后续：日常使用

- 改进首次配置流程及 Linux/macOS 官方隧道客户端安装说明。
- 补足英文深度文档和平台示例。
- 在明确事务与恢复语义后，评估 Git 写操作、二进制产物回存和长期作业管理。
- 基于真实任务评估工具数量和可发现性，保持常用文件操作容易被模型调用。

## 暂停：自动原文件附件

纯 MCP 原文件自动变成可读附件、浏览器自动化、Actions/HTTPS 和第三方公网通道暂停开发。恢复前需用户重新确定范围，并满足：

- 宿主接口有明确支持依据；
- 在真实 ChatGPT 中对合成文件完成正文问答，而非仅打开组件；
- 不增加未经接受的扩展、云服务或每文件复杂操作；
- 有跨平台配置、权限、重试和失败恢复设计。

本路线不是发布日期或功能承诺。
