# WebCodex 本地控制中心（0.16.0-preview.14）

本地控制中心可以编辑配置、管理工作区、切换权限与功能、更新密钥，以及启动、停止和重启由面板管理的 MCP 服务。页面使用本地资源，适配桌面与窄屏，不需要额外云服务或浏览器扩展。原有文件、会话与作业只读浏览保留在“文件与会话”入口。

## 启动与配置

在已构建项目的终端运行：

```text
node dist/src/cli.js connect --config /absolute/private/config.toml
```

使用 v2 配置时，`connect` 默认同时启动本地控制中心和 MCP 服务，同一次启动的服务可直接在页面启停、重启。使用项目默认配置时可省略 `--config`。Windows 可用 `D:/WebCodex/config.json`，不同设备填写各自的真实路径。面板、`connect` 和配置管理命令使用同一份 JSON/TOML，选择顺序及路径规则见[统一配置](local-configuration.md)。

可选端口设置属于同一配置：

```toml
[localPanel]
port = 8767
```

JSON 对应 `"localPanel": { "port": 8767 }`。端口为 1024–65535 的整数，默认 8767。监听地址固定为 `127.0.0.1`，不提供公开地址、域名或远程绑定配置。面板端口与 `http.port` 的 MCP HTTP 端口相互独立。

面板就绪后，终端通过 stderr 在独立一行打印完整可点击 URL，例如 `http://127.0.0.1:8767/#token=...`。示例中的省略号需替换为终端实际生成的凭据，不能只打开无凭据的地址。在同一台设备的浏览器中打开完整 URL，并保持终端运行。`connect` 遇到面板端口占用，或面板端口与本次 HTTP 服务端口相同时，会临时选择空闲回环端口，以本次输出的实际 URL 为准；不修改配置、不关闭旧页面。连接检查或服务启动失败、发现外部实例时，已启动的页面保留供检查和修复，不会显示连接成功或接管外部实例。

只需编辑配置时运行 `node dist/src/cli.js panel`，它不自动连接，需要时点击“启动服务”；该命令支持 `--port 8777` 临时指定端口，不修改配置。`connect --no-panel` 保留无页面连接方式；`connect --doctor-only` 只检查，不启动页面。底层 `serve` 不附带控制中心，保留独立 MCP 协议启动方式。

**完整启动 URL 含本次面板的临时凭据，需要保密。** 不粘贴到 ChatGPT、issue、共享截图或公共日志，也不用配置中的 API key 替代它。凭据只对本次面板进程有效，停止或重启后旧链接失效；这不是承诺在固定几分钟后自动过期的登录链接。

页面从 URL fragment 取出凭据后清除地址栏片段，尝试保存在该本机页面会话的 `sessionStorage`，刷新可继续使用；浏览器禁止会话存储时仅保留在当前页面内存。它不写长期 `localStorage`，不加载外部脚本、字体、CDN 或分析资源，请求只发到本机同一来源。清空页面会话后需从当前终端重新打开完整链接。页面地址和 API 都有 Host/Origin 检查，只接受当前面板端口上的回环地址 `127.0.0.1` 或 `localhost`，拒绝局域网、公网和其他主机名。

Linux 服务器没有图形界面时，面板仍只监听服务器的 `127.0.0.1`。在本机建立 SSH 本地转发，把服务器面板端口映射到本机（端口按启动命令实际输出替换）：

```sh
ssh -N -L 18777:127.0.0.1:8777 user@server
```

然后在本机浏览器打开启动命令输出的完整凭据链接，并将其中的端口改为本地转发端口（上例为 `http://127.0.0.1:18777/#token=...`）。也可以使用等价的 `http://localhost:18777/`；Host 和 Origin 的两种回环拼写均受同样的令牌校验，转发端口可以与服务器端口不同。不要把服务器面板绑定到 `0.0.0.0` 或通过公网暴露。

## 配置与服务管理

| 页面 | 操作 |
| --- | --- |
| 概览 | 设备名称、配置位置、保存/应用状态、服务启动/停止/重启 |
| 工作区 | 新增/移除条目、名称、目录、只读/可写、启停、目录不可用策略 |
| 功能与权限 | 一键完全本机访问、真实写入自检、本机命令执行总开关、Codex 会话读取及目录、诊断、原有文件组件设置 |
| 连接设置 | 隧道开关、Tunnel ID、API key、代理、客户端路径/版本/哈希、传输方式及 HTTP 令牌 |
| 高级设置 | Node/Git/rg/工具目录、面板端口、文件/分块预算、执行时间和输出限额 |

编辑首先形成页面草稿。“检查配置”不写文件；“保存配置”检查读取时的 SHA-256，原子写回同一 JSON/TOML，并保留未编辑字段及受支持的 TOML 注释。“保存并重启”只应用本次确认的保存版本；其他编辑器修改文件会触发冲突，不能盲目覆盖。

校验失败时，页面列出具体字段和修改要求，在输入框旁显示红字和红色边框，并自动切换到首个错误所在页面。点击错误列表可定位其他字段；修改后可重新“检查配置”。例如，客户端摘要格式错误会明确要求 64 位十六进制字符，超时设置冲突会指出默认值不能超过最大值。校验失败不会保存配置或重启服务，草稿和已输入密钥仍保留。

“一键完全开放”把所有已启用工作区改为可读写，并设置 `execution.mode="trusted-host"`、`execution.commandPolicy="all"`；保存并重启后，可运行本机可找到的程序，无需逐个放行。“立即检测实际权限”读取磁盘上的已保存配置，在每个可写工作区创建、读回并删除随机临时文件，分别报告 `READ_ONLY`、目录不可用和操作系统 `EACCES/EPERM/EROFS`。测试不执行用户命令，不提升权限，也不把临时文件当作项目变更保留。

“本机命令执行”仍可单独开启和关闭。旧配置缺省使用兼容的 `allowlist` 策略，页面提供一次切换到统一开关的入口，不会在仅查看配置时扩大权限。已有程序预设、固定参数和环境配置保留，页面不再展示逐项程序授权表。新安装直接使用统一开启状态；升级已有配置时保持原权限，直到用户明确点击或运行 `webcodex-mcp access full`。

API key 和 HTTP 令牌只显示是否已配置，留空保留原值，填写新值替换，单独清除才删除。读取接口不返回现有密钥、环境值或固定执行参数。复杂参数/环境仍可通过原 CLI 或配置文件维护。设备 ID、状态目录与工作区 UID 不通过普通表单修改。

新增工作区需要实际本机目录；相对路径和变量相对于所选配置解析。更换目录会重新校验身份，移除条目不删除磁盘文件。链接、受保护目录、重叠权限和已登记 worktree 的检查继续生效。新增访问范围、开放写入、开启程序执行等变更会在保存前显示具体摘要；`trusted-host` 使用本机账号权限，并非操作系统沙箱。只读工作区不能启动命令，但可写工作区中启动的程序仍可能访问本机账户有权访问的其他目录和网络。

默认 `connect` 与页面的启动操作均按 `server.transport` 选择服务：stdio 模式启动已验证的官方 Secure MCP Tunnel；HTTP 模式启动本机 MCP HTTP 服务。HTTP 就绪表示本机接口启动，不代表 ChatGPT 已接入。启动期间配置被改动时，子服务会拒绝不匹配的配置版本。

本版默认 `connect` 创建的服务由同一次启动的控制中心管理，无需原终端交接。旧版本、`connect --no-panel` 或独立 `serve` 启动的服务仍显示为外部启动器，需先在原终端正常停止一次，再从面板启动。面板不按记录的 PID 杀进程，不自动删除启动锁。停止/重启前只读检查作业：有活动作业或状态无法确认时拒绝操作；重启等待自有服务退出后再启动。HTTP 子进程使用私有 IPC 正常关闭，不强退 Windows 进程。

作业检查是检查时刻的状态，尚未实现对所有新 MCP 请求的原子排空；应在当前作业结束后操作。关闭面板终端会尝试停止其管理的服务；作业仍在运行时保留面板并提示稍后重试，外部服务不受影响。面板端口修改在下次启动面板生效，“保存并重启”重启的是 MCP 服务。

页面可修复语法有效但已不可用的工作区/Codex 目录。文件无法解析、无效配置变量等错误仍需先修正；旧 version 1 配置需先迁移，不能静默当作 version 2 保存。

管理接口不作为 MCP 工具暴露。写请求要求面板令牌、严格同源、JSON 和有界大小；不提供 CORS。查看状态仍使用只读 SQLite，不初始化第二个 App/StateStore、不修改活动服务租约。

## 读取状态

面板将几类事实分别展示：

| 内容 | 能说明什么 |
|---|---|
| 设备名称、ID、版本和配置路径 | 当前面板读的是哪份本机配置与构建 |
| 工作区根、权限和健康状态 | 当前可浏览的授权目录；离线或身份变化的目录会单独显示 |
| 官方隧道进程、MCP 就绪、OpenAI 轮询 | 当前获得的连接证据；面板能打开不等于 ChatGPT 已连通 |
| 工具响应计数与协议诊断 | 是否观察到请求及受限错误类别；响应已发送不证明业务成功或网页呈现 |
| 作业状态、退出码和输出 | 只读数据库中的记录，不是实时终端或操作系统进程存活证明 |

点击刷新重新获取状态。`unknown`、证据不足、离线与失败应按其原含义处理。输出只提供初始记录的有界片段，并进行常见凭据脱敏；需要完整输出或持续等待时，在 ChatGPT 使用相同 job ID 调用 `exec_poll`、`exec_wait` 或 `exec_tail`。面板没有启动、取消作业或发送标准输入的接口。

面板允许查看离线工作区的诊断，不因此放宽目录访问权限。目录被替换、关闭或不再符合授权策略时，不能用旧页面继续浏览。缺少状态数据库时显示暂无记录，不会为了展示状态启动服务或创建数据库。

## 定位原文件并在 ChatGPT 上传

1. 在面板选择目标工作区，进入目录并点击文件，也可输入工作区内相对文件路径。
2. 查看名称、绝对路径、大小、基于扩展名的 MIME 提示，以及预算内可计算的 SHA-256。
3. 点击“复制完整路径”，在 ChatGPT 的原生文件选择框中选取文件；或点击“打开所在目录”，从本机文件管理器把原文件拖入 ChatGPT。
4. 在 ChatGPT 中等待附件处理完成，再提问文件正文中未在提示里给出的内容，核对回答。

Windows 文件选择框通常可以在文件名栏粘贴完整路径。其他系统使用其文件选择器或文件管理器的路径定位功能；如果自动复制不可用，面板会选中路径供手工复制。“打开所在目录”只请求文件管理器打开父目录，不执行该文件，也不会把面板链接当成附件上传。

面板不解析 PDF、Office、压缩包或图片，不做 OCR、转换、文本提取或摘要。哈希基于原始字节，预算取自 `limits.fileReadMaxBytes`，默认 16 MiB。超过预算显示“未计算哈希”，仍保留定位、复制路径和打开所在目录；不截断文件，也不限制 ChatGPT 的原生上传大小。

面板没有向 ChatGPT 上传文件的接口，也不观察外部聊天的附件状态，因此文件信息中的 `upload_status: not_uploaded` 和 `model_access: unverified` 不会因用户另行上传而自动变为成功。只有在 ChatGPT 中实际选择附件并核对正文回答，才能确认那份附件可读。文件之后有修改，应重新核对上传版本。详见[原文件说明](original-files.md)。

## 接续本地 Codex 会话

在“功能与权限”中开启 Codex 会话读取、设置正确的 Codex home 并保存，即可刷新面板的会话视图；要让 MCP 工具使用新设置，还需重启服务。也可通过 CLI 修改同一配置，再重启面板载入：

```text
node dist/src/cli.js codex enable --home /absolute/codex-home --config /absolute/private/config.toml
```

面板只读列出当前工作区匹配的会话索引。选择“复制接续请求”后，将请求粘贴到已连接这台设备的 ChatGPT 对话。请求要求模型先通过 `system_status` 核对设备，再用 `codex_session_handoff` 读取所选会话的可见上下文，检查当前文件与 Git 状态后说明下一步。

这一步复制的是接续请求，不是把历史全文偷偷加入当前聊天。面板不恢复模型隐藏上下文、不修改 Codex 数据库、不重放旧命令或启动原进程。会话索引有分页及扫描预算，当前页没有匹配记录不一定意味着不存在历史。详情见[Codex 应急接续](codex-emergency.md)。

## 配置改变与常见问题

页面保存后会刷新查看用的配置快照；MCP 服务继续使用启动时的版本，直到完成重启。若保存成功后其他编辑器又改动文件，页面保留准确保存回执并停止自动重启，要求刷新核对。面板端口变化需在下次启动面板时应用。

- **端口占用**：默认 `connect` 自动选择空闲回环端口，打开本次输出的完整链接；单独运行 `panel` 时可使用 `--port 8777`。不要把面板绑定到公网。
- **等待本机授权/401**：使用当前面板终端打印的完整 URL；旧进程的 token、配置 API key 都不能替代。
- **隧道未连通**：检查页面的连接配置和运行状态，必要时按[连接指南](chatgpt-setup.md)检查 `tunnel status`。面板可以重启自己启动的隧道；外部启动器仍需在原终端正常停止一次。
- **文件哈希超预算**：可继续通过文件选择器或拖拽上传原文件，无需调大 MCP 传输限额。
- **作业或会话暂无记录**：检查配置、工作区、历史读取开关和记录范围，不把“暂无记录”当作进程已结束。
- **GPT 只说“安全检查拦截”**：这不是 WebCodex 错误证据。要求它实际调用 `system_status`、`workspace_list` 和对应写入工具，并报告工具名及完整错误码。若没有工具调用，则问题发生在 ChatGPT 工具调度层；若得到 `READ_ONLY` 或 `ACCESS_DENIED`，按页面实际权限检测结果处理。

本版不提供浏览器自动附件注入或跨设备统一调度。Actions / Cloudflare 方案已保留为[后续路线](roadmap.md)，不属于面板的使用步骤。
